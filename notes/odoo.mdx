## Setup

Odoo 17, Python 3.10.12, Postgres 14, Adminer

Install [docker](https://docs.docker.com/engine/install/ubuntu/)

Run Postgres with docker 

```bash title="postgres/compose.yml"
# Use postgres/example user/password credentials

services:

  db:
    image: postgres:14.22-trixie
    restart: always
    # set shared memory limit when using docker compose
    shm_size: 128mb
    # or set shared memory limit when deploy via swarm stack
    #volumes:
    #  - type: tmpfs
    #    target: /dev/shm
    #    tmpfs:
    #      size: 134217728 # 128*2^20 bytes = 128Mb
    environment:
      POSTGRES_USER: hehe
      POSTGRES_PASSWORD: 123123
    volumes:
      - postgres_data:/var/lib/postgresql/data
    ports:
      - "5432:5432"

  adminer:
    image: adminer
    restart: always
    ports:
      - 8080:8080

volumes:
  postgres_data:
```

```bash
docker compose up
```

Access database via docker compose

```bash
docker exec -it myproject-db-1 psql -U odoo -d mydb
```

`docker exec`: Run a command inside an already running container

`-it`: Open interactive terminal mode

`myproject-db-1`:  Container name

`psql`:  PostgreSQL command line client

`-U odoo`: Connect with PostgreSQL user odoo

`-d mydb`: Connect to database mydb

## Custom module

### Composition of a module
An Odoo module can contain a number of elements:


<HighlightText>Business objects</HighlightText>

A business object (e.g. an invoice) is declared as a Python class. The fields defined in these classes are automatically mapped to database columns thanks to the ORM layer.


<HighlightText>Object views</HighlightText>

Define UI display

<HighlightText>Data files</HighlightText>

XML or CSV files declaring the model data:

- views or reports,
- configuration data (modules parametrization, security rules),
- demonstration data
- and more


<HighlightText>Web controllers</HighlightText>

Handle requests from web browsers

<HighlightText>Static web data</HighlightText>

Images, CSS or JavaScript files used by the web interface or website


### Module structure

Custom restful api

```bash
custom_rest_api/
├── __init__.py # import instruction
├── __manifest__.py # declare
├── controllers/
│   ├── __init__.py
│   └── api.py
└── models/s
    └── __init__.py
└── security/
    └── ir.model.access.csv
```


```python title="__manifest__.py"
{
    "name": "Custom REST API",
    "version": "1.0",
    "depends": ["base"],
    "installable": True,
    "application": False,
}
```

Update odoo.conf

```
addons_path = odoo/addons, my_addons
```

**The flag `-i` `-u`**

`-i` Install

Use this  when first create the module, after installed Odoo remembers it in DB.

- What it does: It registers the module in the ir.module.module table

- When to use: Add new module

`-u` Update

Later you change things like edit model

Odoo does NOT automatically reload all module metadata from filesystem every startup.

So it tells Odoo to scan your module's source code and "re-sync" the database with the files.

**Example**

Initial install
```bash
-i custom_rest_api
```

Your model:
```bash
class Student(models.Model):
    _name = 'school.student'

    name = fields.Char()
```
DB table created.

Later you add field

```bash
age = fields.Integer()
```

If you ONLY restart server:

```bash
python odoo/odoo-bin -c odoo.conf
```
the database schema is NOT updated.

`age` column does not exist.

You get errors.

Then You Use -u

```bash
-u custom_rest_api
```

Odoo update the database


### Define model

Minimun defintion of model

```python title="models/test_model.py"
from odoo import models

class TestModel(models.Model):
    _name = "test.model"
```

How the corresponding Python file is imported

1. The model is defined in the file `custom_module/models/test_model.py`

2. The file `test_model.py` is imported in `custom_module/models/__init__.py`

2. The folder `models` is imported in `custom_module/__init__.py`

Then run odoo to create new table

```bash
./odoodev -u custom_module
```
